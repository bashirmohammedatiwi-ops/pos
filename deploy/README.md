# FOT Web Hub (VPS)

نقطة البيع وSQL تبقى في المحل. السيرفر يخزّن **نسخة آمنة للبائع** ترفعها لوحة التحكم باستمرار. لا نفق.

## المنافذ على السيرفر

| منفذ | الخدمة |
|------|--------|
| **4700** | البوابة العامة |
| **4701** | تطبيق البائعين |
| **4702** | الموظفون — لاحقاً |
| **4703** | تطبيق المدراء |
| **4705** | استقبال المزامنة من المحل فقط |

لا يُفتح 80 أو 443 أو 3000 أو 5000 من هنا.

## تحديث الـ VPS

```bash
cd ~/pos
git restore deploy/up.sh || git checkout -- deploy/up.sh
git pull origin main
cd deploy
chmod +x update.sh up.sh
./update.sh
```

يجب أن تظهر الحاويات: `hub` و`seller` و`manager` و`gateway`. افتح 4700 و4701 و4703 و4705 في جدار النار/لوحة Contabo.

## المفاتيح السرية (إلزامية)

المفاتيح الافتراضية القديمة منشورة في git، لذلك **يرفض الـ hub التشغيل** بها، ويتوقف `up.sh` قبل إعادة تشغيل أي حاوية (تبقى الحاويات الحالية تعمل). لا تضع القيم الحقيقية في git أبداً — مكانها `deploy/.env` على الـ VPS (ملف مستثنى من git) وإعدادات سيرفر المحل فقط.

| المتغير في `deploy/.env` | ما هو |
|------|--------|
| `FOT_HUB_SYNC_KEY` | مفتاح المزامنة بين سيرفر المحل والـ hub — نفس القيمة في الطرفين، 24 حرفاً على الأقل |
| `FOT_HUB_JWT_KEY` | توقيع جلسات البائع والمدير وتطبيق الفريق — يبقى على الـ VPS فقط، 32 حرفاً على الأقل. يولّده `up.sh` تلقائياً إن كان ناقصاً أو افتراضياً |
| `FOT_HUB_JWT_HOURS` | عمر الجلسة بالساعات (الافتراضي 720 = 30 يوماً) |
| `FOT_HUB_REFRESH_DAYS` | مدة قبول تجديد الجلسة بعد انتهائها (الافتراضي 30 يوماً) — بعدها يلزم الدخول من جديد |

خطوات أول مرة (أو لتغيير مفتاح المزامنة):

1. ثبّت سيرفر المحل 2.3.9 أو أحدث (فيه حقل المفتاح في لوحة التحكم). يستمر بالمفتاح القديم حتى تُدخل الجديد، فلا تنقطع المزامنة قبل الخطوة 2.
2. على الـ VPS شغّل `./update.sh` (أو `./up.sh`). يولّد المفتاحين تلقائياً إن كانا مفقودين أو افتراضيين، ويطبع **مفتاح المزامنة** في آخر الرسالة.
3. في لوحة التحكم: تطبيق الفريق ← التحديثات والإشعارات ← «الربط مع خادم الفريق» ← الصق المفتاح ← «تجربة وحفظ». يُحفظ على سيرفر المحل في `%ProgramData%\FOT.Pos\hub-sync.key` ويبقى بعد تحديث المثبّت — **لا حاجة لإيقاف السيرفر**. تتوقف المزامنة فقط بين الخطوتين 2 و3.

لعرض المفتاح مرة أخرى على الـ VPS: `grep FOT_HUB_SYNC_KEY ~/pos/deploy/.env`. بديل متقدم: `SellerWeb:SyncKey` في `appsettings.json` أو متغير البيئة `SellerWeb__SyncKey` (يتقدم على المحفوظ من لوحة التحكم).

تغيير `FOT_HUB_JWT_KEY` (أول تشغيل بعد هذا التحديث) يُنهي كل الجلسات القديمة مرة واحدة: البائعون والمدراء والموظفون يدخلون من جديد برموزهم، وأجهزة الموظفين تبقى مربوطة كما هي.

للتطوير والاختبار على جهازك فقط: `FOT_HUB_ALLOW_DEV_KEYS=1` يسمح بالمفاتيح الافتراضية.

## الجلسات وإلغاؤها

- جلسة الموظف تسقط فوراً (ومعها قناته الحية) عند: توليد رمز جديد له، أو «فك ربط الجهاز»، أو إيقاف حسابه أو حذفه. إعادة التفعيل لا تُحيي الجلسة القديمة.
- إيقاف المدير أو حذفه يُغلق قناته الحية فوراً ويرفض طلباته.
- القنوات الحية تعيد المصادقة كل 25 ثانية، فتُغلق عند انتهاء الجلسة.

## على جهاز المحل

ثبّت خادم نقطة البيع **2.2.67** أو أحدث. بعد تشغيل `FOT POS Server` يرفع حسابات البائعين والمدراء وبيانات المتابعة إلى `http://187.124.23.65:4705` كل دقيقة، وفوراً عند توليد رمز أو حساب مدير من **حسابات الويب**.

لا حاجة لملف نفق.

ثم افتح `http://IP-السيرفر:4701` للبائع و`http://IP-السيرفر:4703` للمدير.

## ماذا تُمرَّر من البوابة؟

البوابة تمرّر `/auth/seller-*` و`/api/seller/` و`/auth/manager-*` و`/api/manager/`. باقي الـ API مرفوض.

الحسابات تُولَّد من لوحة تحكم المحل: **الفريق والحوافز → حسابات الويب**.
